# v1.2.3 Release Notes（存档）

## Highlights

- **External links now work**: clicking any link inside the app opens it in your system default browser instead of silently doing nothing.
- **Fixed "启动尝试 1/6" startup failure** on macOS when launched from Finder/Dock: dsh's child processes (MCP servers, workers) couldn't find `node` because GUI apps get a stripped PATH.
- **Stable macOS signing** so permission prompts (removable volumes / Full Disk Access) are asked **once**, then remembered across every future update.

## Changes

### Added
- `docs/RELEASE.md`: documented release process, release-notes template, and signing notes.
- DMG now bundles **Install DSH Desktop.command** — double-click to install (replaces old copy, removes quarantine).
- Unit tests for the URL classification logic (`is_app_url`).

### Fixed
- **Dead link clicks in the embedded webview** (`target="_blank"`, `window.open`, same-tab external links). Root cause: WKWebView silently drops new-window requests when no handler is registered. Now a `new_window_req_handler` + `navigation_handler` route external URLs to the default browser; loopback / about / blob / data URLs keep in-app navigation; `file://` and `javascript://` are denied.
- **"env: node: No such file or directory"** retry-loop on GUI launch. The watchdog script now prepends the resolved node bin dir to `PATH`, so the whole dsh child tree can re-exec node by name.
- CI Info.plist version was hardcoded; it now derives from `Cargo.toml`.

### Changed
- macOS builds are signed with a fixed identifier (`com.dshdesktop.app`) plus the `com.apple.security.files.removable-volumes` entitlement. CI falls back to ad-hoc signing (with a build warning) until `MACOS_SIGNING_P12` / `MACOS_SIGNING_PASSWORD` secrets are configured — see `docs/RELEASE.md`.

## Install

| Platform | Asset |
|---|---|
| macOS (universal) | DSH-Desktop-macos-universal.dmg |
| Windows x64 | DSH-Desktop-Setup-x.y.z.exe |
| Linux x64 | DSH-Desktop-linux-x64.tar.gz |

### macOS
1. Download the DMG and open it.
2. Double-click **Install DSH Desktop.command**.
3. First launch asks **once** for removable-volume / disk access — click Allow. Locally-built (signed) versions never ask again; CI builds ask once per install source.

### Windows
Run the Inno Setup installer.

### Linux
```bash
tar xzf DSH-Desktop-linux-x64.tar.gz && cd DSHDesktop && sudo ./install.sh
```
